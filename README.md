# XBOX-Inspector 0.3.0

Настольный инструмент для **инвентаризации Xbox Series X|S сборок**, проверки
открытых (незашифрованных) диапазонов данных и **preflight-оценки готовности к
запуску**. Преемник SimuXBOX 0.1.0 (Python), переписан на **Rust**.

Исходная папка открывается **только на чтение**. Все артефакты (отчёты,
свежие индексы) пишутся в отдельный каталог `work\` рядом с программой.
В поставку не включены бинарники игровых сборок, ключи и закрытые компоненты.

В 0.3.0 исправлен переход между окнами чтения ZLIB. Потоковая проверка
разделяет ранее подтверждённые диапазоны, дополнительные индексы и новый поиск.
Отчёты сохраняются вне исходной папки. В привычном окне доступны три темы
и четыре языка. См. [проверку релиза](VERIFICATION.md),
[реестр 300 проверок](docs/TEST-REGISTER.md) и
[интеграции](docs/INTEGRATIONS.md).

## Что делает инструмент

1. **Инвентаризация**: рекурсивный обход, размеры, mtime, классификация по
   наблюдаемым префиксам: RPF9 (`9FPR`), RDS5/ETPF, PE (DLL / executable /
   без исполняемой точки входа), XVD, `regf`, `mrm_pri2`, PNG, XML, Bink.
   Символические ссылки никогда не разыменовываются.
2. **RPF9**: профиль заголовка (64 байта), граница кандидата каталога
   `[64, word_04)`, SHA-256 заголовка. Статус `ENCRYPTED_OR_UNRESOLVED`
   означает отсутствие подтверждённой открытой таблицы — **не** устанавливает
   алгоритм шифрования и не классифицирует весь файл как шифротекст.
3. **RDS5/ETPF**: полный разбор открытых таблиц границ и дескрипторов текстур
   (ширина/высота/mip/DXGI/array/tile mode), классификация блоков
   (AVAILABLE / TRUNCATED_FILE / SPARSE_GAP / UNSUPPORTED_CODEC / BLOCK_LIMIT /
   EXPANSION_LIMIT / …). Опционально (`--deep`) — побайтная проверка блоков:
   ограничена 64 МиБ на блок, 2 ГиБ на сеанс, ZLIB по RFC 1950 с проверкой
   Adler-32 и конца потока.
4. **Проверка индексированных диапазонов**: вход — файл и независимый список
   уже известных открытых диапазонов (смещение, сохранённая длина, ожидаемая
   длина, SHA-256). Проверка идентичности входа → целочисленные границы →
   ограниченная распаковка ZLIB → SHA-256 выхода → статус. Покрытие считается
   объединением интервалов (пересечения не удваивают байты).
5. **Видео**: проверка открытых записей Bink KB2j/KB2n по встроенному индексу
   (поля заголовка + SHA-256 заголовка и таблицы кадров), либо поиск сканом.
6. **Поиск открытых потоков** (`--scan-open`): ZLIB-потоки в выделенных
   диапазонах RPF9 (data/script/common/story000_script) и Bink в movies.rpf.
   Результат — новый индекс с хэшами распакованных байтов. Это восстановление
   **открытых** данных, не дешифровка.
7. **Preflight запуска**: разбор `MicrosoftGame.Config` и `appxmanifest.xml`,
   поиск объявленного исполняемого файла, статический PE-разбор (машина,
   точка входа, секции, импорты), проверка зависимостей. Если exe отсутствует —
   точный блокер: «В манифесте указан исполняемый файл, отсутствующий в папке».
   Инструмент **не подставляет** DLL или тестовую программу вместо игры и
   **не запускает** игру. Статус «запуск подтверждён» требует
   отдельного успешного опыта с полным разрешённым входом и слоем совместимости
   (XCL/ScarlettX — внешние проекты, оцениваются по их документации).

## Быстрый запуск (Windows, из ZIP)

1. Распакуйте ZIP в любую папку (пробелы и кириллица допустимы).
2. Откройте терминал в корне распаковки и выполните:

   ~~~powershell
   .\Start-XBOX-Inspector.cmd
   ~~~

   либо двойной щелчок по `Start-XBOX-Inspector.cmd`. Launcher запускает
   только инспектор; права администратора не требуются.

В окне: выберите папку сборки → «Проверить». Первый проход — метаданные,
заголовки, preflight и проверка по встроенным индексам. Дополнительные
проверки (глубокие блоки RDS5, поиск открытых потоков, полный SHA-256)
включаются **явно** галочками. Отмена сохраняет целостность журнала.
Ссылки «Открыть отчёт» и «сохранить JSON / Markdown» доступны после
успешного прохода. Для сохранения выберите папку вне исходных файлов.

### Терминал (headless)

~~~powershell
.\bin\XBOX-Inspector.exe scan "C:\путь\к\сборке" --json report.json --md report.md
.\bin\XBOX-Inspector.exe scan "C:\путь\к\сборке" --scan-open
.\bin\XBOX-Inspector.exe scan "C:\путь\к\сборке" --hash-all   # очень долго: сотни ГБ
.\bin\XBOX-Inspector.exe selftest
~~~

## Сборка из исходников

Проверенная цель сборки — `x86_64-pc-windows-gnu`. Нужны Rust 1.100.0 из
`rust-toolchain.toml`, Python 3.11+ для упаковки и MinGW binutils
(`as.exe`, `dlltool.exe`). Установите binutils из доверенного дистрибутива
и укажите папку с этими файлами. C++ используется в отдельном проверочном
эталоне и при сборке приложения не требуется.

~~~powershell
rustup toolchain install 1.100.0-x86_64-pc-windows-gnu --profile minimal
.\packaging\make-zip.ps1 -Binutils 'C:\путь\к\mingw64\bin'
~~~

Если GNU `dlltool` не обрабатывает кириллицу в путях промежуточных файлов,
передайте отдельный путь с латиницей через `-TargetDir 'C:\build\xbs'`.
Готовый ZIP распаковывается и запускается в папке с пробелами и кириллицей.

Зафиксированные зависимости (Cargo.toml workspace):
`sha2 0.10.8`, `flate2 1.0.35` (rust_backend = miniz_oxide), `serde 1.0.210`,
`serde_json 1.0.128`, `quick-xml 0.37.2`, `windows-sys 0.59.0`,
`eframe 0.31.1` (glow), `rfd 0.15.0`. Точные версии — в `Cargo.lock`.

## Маленький тестовый вход

`selftest` создаёт собственные входы в памяти (обычный поток, нулевой выход,
битая Adler-32, обрезанный поток, два сцепленных потока, неверная длина,
превышение лимита, FDICT-словарь) и проверяет учёт перекрывающихся интервалов.
Интеграционные тесты (`cargo test -p xbs-ranges`) additionally гоняют индекс
по временным файлам, включая путь с кириллицей и пробелами, отмену и повтор
после сбоя.

## Схема отчёта

Версионированная схема `xbox-inspector-report/1`. Ключевые поля:
`source_root`, `file_count`, `logical_bytes`, `files[]` (`source_path`,
`source_size`, `prefix_hex`, `file_type`, `catalog_state`, `source_sha256`,
`checked_intervals`, `validation_level`), `runtime_preflight`, `rpf9[]`,
`rds5[]`, `index_verifications[]`, `video_verifications[]`, `open_scans[]`,
`resource_totals`, `coverage[]`, `tests[]`, `notes[]`.

Пример фрагмента:

~~~json
{
  "schema": "xbox-inspector-report/1",
  "tool": "XBOX-Inspector",
  "tool_version": "0.3.0",
  "file_count": 132,
  "logical_bytes": 223906037552,
  "runtime_preflight": {
    "declared_executable": "game_scarlett_master.exe",
    "executable_found": false,
    "launch_ready": false,
    "blockers": [
      "В манифесте указан исполняемый файл, отсутствующий в папке: game_scarlett_master.exe"
    ]
  }
}
~~~

Индексы диапазонов: `xbox-inspector-range-index/1`
(`source_path`, `source_size`, `source_sha256?`, `entries[]`: `id`, `offset`,
`stored_len`, `expected_len?`, `sha256?`, `encoding: raw|zlib`, `kind`).
Встроенные индексы в `indexes\` происходят из проверочных проходов SimuXBOX
0.1.0 и привязаны к снимку (размер + SHA-256). Обновление индекса по результату
нового теста — только отдельным решением; свежие индексы скана сохраняются как
новые файлы в каталоге сеанса `work\scan-…\`, встроенные не перезаписываются.

## Честные ограничения

- Закрытые каталоги RPF9, XVD и `Catalog000.bin` **не расшифровываются**.
  Высокая энтропия и совпадение байтов не объявляются доказательством шифрования.
- Число уникальных ресурсов всей сборки неизвестно: счётчики разделены на
  записи каталога, проверенные диапазоны, уникальные хэши и работоспособные выходы.
- «Запуск подтверждён» не выводится из статических проверок и распаковки.
- Полное хеширование сотен ГБ выполняется только по явному запросу (`--hash-all`).
